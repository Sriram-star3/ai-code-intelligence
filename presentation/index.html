AI Provider Design
Swappable AI backend via claude_client.py

All AI calls go through a single client object mimicking the Anthropic SDK shape. The provider is controlled by one env variable:

# .env
AI_PROVIDER=gemini
# Three options:
mock → free offline responses
claude → real Anthropic API
gemini → real Gemini API ✓
  • No provider-specific imports scattered across the codebase
  • Swap from Gemini to Claude with one env var change
  • Mock provider enables offline development at zero cost
  • Currently active: gemini-3.5-flash-lite
  • Adding a new provider needs only one new shim file

Feature 3
Documentation Drift Detection
  • Every function's AST is hashed at index time and stored in SQLite
  • On re-scan, changed hashes = drifted functions
  • New functions with no docs flagged as "new"
  • Gemini auto-generates a docstring for each flagged function
  • Results show file, function, class, status, and generated doc

  "processed": 3,
  "results": [{

    "status": "drifted",
    "generated_doc": "Walks..."
  }]
}

Built With IBM Bob
AI pair programmer — not just a code generator

IBM Bob was used as the primary development assistant throughout the entire project — reading files before editing, tracking tasks with a live to-do list, and verifying every command output before marking work done.

Core discipline: Bob proposed a plan before every significant change and waited for approval — keeping the developer in full control of all architectural decisions.

Design Decisions
Why we built it this way
Single service deployment
FastAPI serves the built React app as static files. One Railway service, one URL, no CORS in production.
Swappable AI provider
All AI calls through one client object. Switch from Gemini to Claude with one environment variable change.
No filesystem dependency for users
Both Summarize and Diagram accept uploaded files — works on any codebase from any machine.
Minimal dependencies
10-package requirements.txt with only direct dependencies. pip resolves compatible transitive deps per platform.
